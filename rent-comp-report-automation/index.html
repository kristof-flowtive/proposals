01 — Understanding

What you're solving for

Your Claude project already produces a report you like. The hours go into everything around it: exporting from three tools, your assistant checking and adding comps, uploading files and retyping changes into the chat, and doing it again next time from scratch. You want it reliable and repeatable, and organised for 100+ buildings.

Requirement

"Extract the comp data accurately"

Every comp Claude extracts lands as a row with its source file and page, and anything that fails a check (rent out of range, missing beds or baths, same address from two sources) is flagged for your assistant before the report is built.

Requirement

"Consistent every time"

Layout lives in a fixed branded template, not in a chat. Claude fills in the numbers and writes the commentary, so the wording adapts but the pages, fonts and order never change.

Requirement

"Organize by building and by unit"

Buildings, units, comps, reports and lead stats are linked records. Open a unit and you see every report it has ever had; the PDFs sit in a Drive folder per building and unit.

Requirement

"Simple enough for my team to run without technical knowledge"

Your team works in one screen: pick a unit, drop files, press Build report, review, press Send. Nobody opens Make or writes a prompt.

02 — Recommended approach

A small app, with Claude inside it

A Claude Project is a good place to design a report. It isn't a good place to run 500 of them: it has no memory of last week's comps, can't run on a schedule, and lays out the page a little differently each time. So I'd keep your Claude template as the brain and give it a database, a fixed layout and a button.

05 — Photos

Photos from sources you're allowed to use

Pulling images from Zillow, Apartments.com or Google Images is a licensing problem, not a technical one: the photos belong to whoever took them, and those sites' terms forbid scraping. So the system goes down a list of sources that are allowed and flags the rest, instead of filling your reports with images you could be asked to take down.

FIRST

Photo inside the MLS export

If the SmartMLS or RI MLS export includes the listing photo, it's taken from there and placed next to the comp. MLS rules on using listing photos in a comparative report vary, so this is checked against your MLS rules in week one.

THEN

Street View image of the address

Google's Street View Static API returns a front-of-building photo for most addresses, licensed for this kind of use when shown with Google's attribution. Costs well under a cent per image after Google's monthly free usage.

OTHERWISE

Uploaded once, reused forever

Comps repeat week to week. If neither source works, the comp is flagged and your assistant drops in a photo once; it's stored on the comp and reused in every future report.

In practice, after the first few weeks almost every comp already has a stored photo, which gets you close to "no manual photo searching" without the takedown risk.

06 — Reliability

Built so a wrong number can't reach a report unnoticed

01

Extraction is checked, not trusted

Claude returns fixed fields per comp. Rents outside a sensible range for the market, missing beds or baths, and totals that don't match the export are flagged before the comp is used.

02

Tested on your real exports

Milestone one runs on ten of your past exports from each source and compares the rows with what your assistant would have typed. Each source's layout gets its own tested instructions.

03

A person approves before it sends

Scheduled runs build the report and wait as "ready to review". Once you trust a unit's runs, you can switch it to send automatically, one checkbox per unit.

04

Failures land in the Errors table

A Rentometer outage or an unreadable PDF writes a plain-English line against the unit and emails whoever runs reports. Nothing fails silently.

05

Costs capped per run

Re-runs reuse comps already extracted and verified, so Claude only reads new files. Rentometer pulls are counted against your plan's allowance and stop with a warning before they run over.

06

All yours

Airtable, Make, the Claude API key, the PDF template and Drive are all in your accounts. You own every prompt and file; if we part ways, nothing stops working.

10 — Before kickoff

Three things I'll confirm on our first call

Q1
Is the report per unit, per unit type, or per building?
It changes how many reports a run makes and what each one costs. Default: one report per unit on the market, grouped under its building.
Q2
Which Rentometer plan are you on, and does it include API access?
The API is a separate allowance on some plans. Default: we start with PDF uploads and switch Rentometer to direct pulls once access is confirmed.
Q3
Who receives the reports, and should they go out automatically?
Default: reports wait for a quick review and are sent by email from your account; auto-send can be switched on per unit later.
