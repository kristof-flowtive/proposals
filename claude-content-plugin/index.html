01 — Understanding

What you're solving for

The writing is done. About 40 skill files cover content writing, copywriting and social media. What's missing is the part a non-technical user touches: getting it installed without a terminal, connecting Google without a support ticket, and a dashboard where approvals, feedback and results live. That part decides whether the toolkit gets used, and whether the second plugin for another team function can reuse it.

Requirement

"Clicks-only install: no terminal for the end user"

The plugin ships from a private marketplace repo the user adds once in the Claude app, then installs with a click. The same package installs in Claude Code. Nothing runs on the user's machine that needs Node, Python or a key pasted into a file.

Requirement

"Google Workspace connection, plus no-app fallbacks"

Drive, Docs and Sheets go through the Google connectors Claude already offers, so the user signs in with Google rather than you hosting a server and an OAuth app. Every command checks what's connected first and, if nothing is, writes the posting CSV and paste-ready posts and emails as files instead.

Requirement

"Updating the template keeps all saved data"

The dashboard's records live in the page's own storage, keyed by stable ids, with a schema version. A new template reads the old version and upgrades it. That rule is written on day 1, before any tab is built, because it is the hardest thing in the brief to retrofit.

Requirement

"Reading carefully and following them precisely"

Your skill files are packaged, not rewritten. Any change I think one needs goes on a numbered list for your sign-off, and the twice-weekly update says which skills were touched and why.

03 — The dashboard

Five tabs, one record per piece, built to survive updates

Each piece of content is one record with a stable id. The five tabs are views of those records, so a new template version can add a column or a tab without touching what users have already saved. It is built mobile-first, since approvals mostly happen on a phone.

  • ▸Approvals: pieces waiting, approve or send feedback
  • ▸Feedback & revisions: every version and the note that produced it
  • ▸Requests: "we need a launch email by Friday", picked up by the next command
  • ▸Brand hub: the brand config, readable, with the source of each rule
  • ▸Results: shipped pieces by channel and week

04 — Reliability

Built so a non-technical user never gets stuck silently

01

The template update that loses data

Schema version on every record, an upgrade step per version, and a test that loads v1 data into the v2 template before any update ships. This is the M3 acceptance test you named, run on every release after.

02

Google not connected, or half connected

Commands check Drive, Docs and Sheets separately. Docs connected but Sheets not? The post goes to Docs and the posting CSV is written as a file. The user is told which, in one line.

03

Forty skills competing to trigger

Skill descriptions are checked against each other so /social-week doesn't pull in the blog skills. A trigger test list, one prompt per skill, runs in M1 and again before ship.

04

Mac works, Windows doesn't

No shell scripts, no path separators, no hooks that assume bash. Fresh-install tests on a clean Mac and a clean Windows machine, recorded, for M4.

05

Brand settings scattered across files

One config file, written by /setup and editable by hand. Skills read it; none hard-code a brand. That is also what makes the second plugin cheap.

06

Your IP

NDA and IP assignment signed first. Code lives in your GitHub from the first commit; I work in a branch and you merge.

08 — Before kickoff

Three things I'll confirm on our first call

Q1
Which Claude plans will your users be on?
Plugin install in the app, Google connectors and private published pages each depend on plan and admin settings. I'll check every one against your target plans in week 1. Default: individual paid plans, with a note in the README for team admins.
Q2
Does "Google Workspace connection" mean Claude's own Google connectors?
They keep install clicks-only. A custom MCP server would give more control over Sheets, but means hosting and a Google OAuth app. Default: Claude's connectors, with the file fallback covering anything they can't do.
Q3
Where does the dashboard read Results from?
"Results" could mean pieces shipped, or real engagement numbers from the platforms. Default: shipped pieces by channel and week, with engagement as a manual field, since platform analytics would need their own connections.
